# 新視点10: 最悪ケース発散探索 — 平均ケース等価 ⇏ 最悪ケース等価

ソクラテス式問答で見つけた盲点。`tsugi.worstcase` として実装。

## 問答

**Q1.** これまでの全視点（equivalence/decision/rollout/propagation/calibration/
envelope…）は何を入力に取るか？ → *代表データ* か、*与えられた* 2 出力。すべて
**受動的**だ —— 手元のサンプル上で発散の **率/分布** を測る。

**Q2.** では出荷後、その代表サンプルを誰が選ぶのか？ → 開発者だ。だが本番入力を選ぶのは
ユーザー（時に敵対者）。代表分布と本番分布は一致しない。

**Q3.** 代表サンプルで flip率 0.01%・発散 < 許容 なら「移植可」と言えるか？ → 言えない。
測ったのは *平均* であって、認証エンベロープ内に発散を *最大化* する希少入力
（near-cancellation・outlier channel・境界 logit・大規模入力での fp16 飽和）が存在しない
保証はない。**平均ケース等価 ⇏ 最悪ケース等価。**

**Q4.** ならば測るべきは率でなく？ → 認証エンベロープ内で発散を最大化する *入力* と、その
大きさ。受動的サンプリングから **能動的探索** へ。これは ML の adversarial robustness /
fuzzing をベンダー移植に移したもの。

**Q5.** これは既存のどの視点と対をなすか？ → envelope（運用入力が認証前提内か検査）。
envelope は「入力が領域 R に留まれば認証は有効」と言う。worstcase は「R の *内部* でも
発散が許容を超えうるか」を能動的に探す。超える入力が見つかれば、R（認証エンベロープ）が
緩すぎる＝認証が不健全、という反証になる。

## 実装

2 ベンダーのカーネルは（クロスベンダーゆえ）微分不能な黒箱。勾配を使えないので微分フリー
探索（ランダム再開つきヒルクライム）で box 制約内の発散最大化入力を探す。box 制約が要：
無制約だと自明に overflow を見つけてしまう（意味のある反例は *認証エンベロープ内* のもの）。

- `divergence(fn_a, fn_b, x, *, relative)`: 入力 x での 2 ベンダー出力発散。
- `search_worst_input(fn_a, fn_b, x0, *, radius, steps, seed, restarts, bounds)`:
  box 内で発散最大化入力をヒルクライム探索。返す (x_worst, div_worst) は seed 固定で再現する反例。
- `analyze_worst_case(fn_a, fn_b, samples, *, tol, bounds, …)`: 代表サンプルの *典型* 発散と
  探索した *最悪* 発散を対比し verdict。
  - worst > tol（エンベロープ内に許容超過の反例）→ **BLOCK**（envelope が緩い）。
  - worst ≤ tol だが典型の ×10 以上 → **WARN**（平均が最悪を覆い隠す）。
  - それ以外 → OK/INFO。

```
worst-case search (typical=9.44e-04, worst=4.38e-03, ×4.6 vs typical, tol=1.00e-03)
  [BLOCK] worst  エンベロープ内に許容超過の反例: 最悪発散 4.38e-03 > tol 1.00e-03
          (代表は 9.44e-04)。平均ケース検証は良性でも本番で踏みうる → 認証エンベロープが緩い
```

典型発散 9.44e-04 は tol 1e-3 を **下回る**（平均ケースは合格に見える）が、エンベロープ内に
4.38e-03 の反例が在る —— 平均で出荷判断すると本番で踏む。

## 含意

- 検証を「測定」から「探索」へ。代表データの率だけ見て緑にすると、tail 入力で別物になりうる。
- 反例 x_worst は **再現可能な監査成果物**：回帰テスト・bug report・envelope 再設計の起点になる。
- envelope と閉ループを作る：worst が tol を超えたら、認証エンベロープ R を締めるか、移植を
  task 的に未達とする。

## 限界（正直に）

- **探索は健全性でなく反例生成**：反例が見つかれば「不等価の証明」だが、見つからなくても
  「等価の証明」ではない（探索の網羅性に依存）。fail-safe 側ではない非対称性に注意。
- **ヒルクライムは局所最適に嵌りうる**：薄い manifold（厳密な near-cancellation）は到達困難。
  単調・滑らかな発散面では確実だが、孤立した壊滅入力は取り逃しうる（ランダム再開で緩和）。
- **box（エンベロープ）の与え方が結論を決める**：広すぎれば自明な overflow、狭すぎれば
  反例を逃す。意味ある box は envelope（視点）の認証領域と一致させるべき。
- **黒箱前提**：勾配が使えれば（CPU リファレンス経由で）より鋭い探索が可能（将来課題）。

検証連鎖に *入力空間の探索* 次元が加わる：これまでの受動的測定（与えられたデータ上の率）に、
能動的反証（エンベロープ内の最悪入力探索）が対になる。envelope が「領域を定義」し、
worstcase が「その領域を突く」。
