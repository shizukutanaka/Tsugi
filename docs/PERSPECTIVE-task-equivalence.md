# 新視点8: タスクレベル等価性 — 判断は数値でなく決定で測る

ソクラテス式問答・第8ラウンド。`tsugi.decision` として実装。

## 問答

**Q1. これまでの全 7 視点は何を測ってきたか？**
「数値がどれだけ違うか」—— max_abs / rel / 系統バイアス / run-to-run ノイズ。すべて
*テンソル空間* の差。

**Q2. 開発者が出荷するのはテンソルか？**
否。出荷するのは **タスクの判断** —— 分類の argmax、言語モデルの選択トークン、検出の
しきい値判定。ユーザーが見るのは logit の値でなく「どのクラス/トークンが選ばれたか」。

**Q3. 数値発散とタスクの判断は同じものか？**
否。**decouple している**。
- **スケール不変**: logit を 10 倍すれば abs 誤差も 10 倍になるが argmax は不変
  → 判断フリップ率は同一。max_abs は判断を測れていない。
- **数値等価 ⇏ タスク等価**: 巨大な数値発散でもマージンが大きければフリップ 0、
  微小な発散でも near-tie ならフリップ。両者は必要十分の関係にない。

**Q4. では何が判断のフリップを支配するのか？**
局所 **マージン（top1 − top2）**。発散 δ が判断を覆すには **margin < 2δ** が *必要*
（十分ではない）。ゆえにフリップ率 ≤ P(margin < 2δ) という保守的な上界が成り立つ。

**Q5. これは既存視点とどう関係するか？**
**翻訳層**。数値の床（calibration の √K·u）も HW の床（nondeterminism のノイズ）も、
*タスク影響* に翻訳して初めて意味を持つ。橋は **マージン分布**:
発散 δ → P(margin < 2δ) → 判断フリップ率。タスク相対の許容は固定 atol でなく
マージン分布であり、検証の最終単位は **テンソルでなく決定**。

## 実証（numpy・CPU）

2 万サンプル・1000 クラスの logit にクロスベンダー数値発散 ε を加え、argmax の
フリップ率を測る:

```
eps=1e-3: max_abs=0.008  判断フリップ率= 0.24%  フリップ群マージン中央値=0.001 vs 全体0.212
eps=1e-2: max_abs=0.082  判断フリップ率= 2.60%  フリップ群マージン中央値=0.009 vs 全体0.212
eps=1e-1: max_abs=0.816  判断フリップ率=23.86%  フリップ群マージン中央値=0.069 vs 全体0.212
```
→ フリップは **低マージン（near-tie）の裾に集中**する（フリップ群の中央値 ≪ 全体）。

**スケール不変性（max_abs は判断の悪い代理）**:
```
logit 等倍 : max_abs=0.082  フリップ率=2.60%
logit 10倍 : max_abs=0.816  フリップ率=2.60%   ← abs 誤差 10 倍でもフリップ率は同一
```

**P(margin < 2δ) は実フリップ率の上界**（保守的・fail-safe）:
```
eps=1e-3: 実 0.24%  ≤ 予測 0.76%
eps=1e-2: 実 2.60%  ≤ 予測 8.98%
eps=1e-1: 実23.86%  ≤ 予測60.81%
```

**数値発散 ⇏ タスク発散**: マージンの大きい（確信した）モデルは max_abs≈0.37 の
相当な数値発散でも判断フリップ率 < 0.5% に留まる。

## 含意

- 検証の最終単位は **テンソルでなく決定**。「数値がどれだけ違うか」でなく
  「何 % の予測がベンダー間で変わるか」を問う。
- デプロイ判断には数値 atol でなく **タスク予算**（例 フリップ率 < 0.1%）を使う。
- フリップは near-tie 裾に集中するのが健全。**確信予測まで変化するなら系統的発散を疑う**
  （decision の健全性チェック）。これは calibration の系統バグ検出とタスク空間で呼応する。
- 数値検証（視点 1-7）は依然必要 —— だが「目的」でなく「タスク影響を予測する手段」。
  橋は margin 分布。

## API

```python
from tsugi.decision import (
    margin,                # top1-top2（判断の頑健さ）
    flip_rate,             # 判断フリップ率（スケール不変・ユーザーに見える差）
    predicted_flip_bound,  # P(margin<2δ)= 数値発散→タスク影響の保守的上界
    compare_decisions,     # タスクレベル等価判定（フリップ率 vs タスク予算）
    decompose_divergence,  # 系統(argmax保存的)成分と残差(フリップを起こす成分)に分解
)
```

## 追補3 — 同点（tie-break 規約）による偽フリップ

`flip_rate` は argmax の変化を「ベンダー発散」と帰属する。だが np.argmax は同点で先頭
index を返す *規約*。2 ベンダーが異なる規約（first/last）を使うと、**数値が完全一致でも**
判断がフリップする —— ハード発散でなく tie-break 規約の差。量子化（int8/fp8）・マスク（-inf）で
多発する（実測: 整数 logit で同点率 29.5%、数値一致なのに規約差で flip 29.5%）。

`tie_rate(logits, eps)` が top1==top2（差 ≤ eps）の率を露出し、`compare_decisions` は
同点率が高いと WARN する。tie_rate が高い領域では flip_rate の「発散」への帰属は信頼できない
（規約依存）—— この区別を明示するのが honest。

## 追補2 — 生成タスク向け top-k / top-p（nucleus）候補集合フリップ

argmax は分類前提。LLM 生成は top-k/top-p から次トークンを選ぶので、argmax だけでなく
**候補集合**の一致が重要。`topk_flip_rate(a, b, k)` は top-k インデックス集合（順不同）が
ベンダー間で変わるサンプル率を返す。k=1 で argmax フリップ率に一致し、k で単調増加・
スケール不変。候補が rank k と k+1 の境界を跨ぐと flip = 生成の「選択肢の安定性」を測る。

`nucleus_flip_rate(a, b, p, temperature)` は top-p（nucleus）集合の一致を測る。nucleus は
集合サイズが可変で *確率依存*（softmax(logit/temp) の累積が p に達するまで）なので、argmax/
top-k 集合と違い **スケール不変でない** —— logit スケール=温度で nucleus が伸縮する。つまり
温度設定がベンダー間一致に効く（honest な区別。実測: x1=93.8% → x5=41.0%）。これで決定空間の
等価判定が分類（top-1）から生成（top-k 集合・top-p 集合）へ広がる。

## 追補（arXiv:2511.00025 の取り込み）— 系統 vs 残差の分解

FP ノイズは独立ガウスでなく **構造的（相関）**（arXiv:2511.00025）。この系統成分のうち
**per-sample のスケール α と切片 c**（b ≈ α·a + c）は argmax を保存する（順序不変）ので
判断を覆さない。ゆえにフリップ率の bound は total δ でなく **残差**（α,c を最小二乗で除いた
成分）で評価すべき。

実証（numpy）:
```
一様シフト       flip=0.00%  total_δ=0.51(bound 97%)  残差bound 0.0%
純スケール×1.5   flip=0.00%  total_δ=0.50(bound 97%)  残差bound 0.0%
乱雑0.05        flip=7.83%  total_δ=0.05(bound 26%)  残差bound 26%（上界成立）
混合            flip=6.38%  total_δ=0.50(bound 97%)  残差bound 26%（上界かつ正確）
```

→ `decompose_divergence(a,b)` が `systematic_frac` を返し、`compare_decisions` の bound は
残差ベースになった。**数値的に大きくても argmax 保存的な系統発散ならタスク等価**（INFO で明示）。
これは calibration（系統バイアスを *数値* の懸念として検出）と対をなす: 同じ系統成分が
*数値* では要注意でも *タスク* では無害でありうる —— 両層を併せて初めて正しく判断できる。

## 追補: 貪欲だけでは出荷形態を覆えない（温度サンプリングと TV 距離・A-9/Q32）

本視点は「判断は数値でなく決定で測る」として argmax フリップ率を中心に据えた。だが
**実運用 LLM は温度サンプリングで出力する**。そこでは同じ logit 発散が「どちらの語を
選ぶか」でなく **出力分布の差** として現れ、argmax フリップ率はこれを捉えない。

### argmax と softmax の不変性は違う（この追補の核心）

| 変換 | argmax | softmax（温度 T） |
|---|---|---|
| shift `z+c`（一様） | 不変 | **不変** |
| scale `α·z` | 不変 | **非不変**（＝温度を T/α に変えるのと同じ） |

この非対称のため、既存の発散量はどちらもサンプリングに流用できない:

- `residual_divergence_rms`（argmax 用・アフィン成分を除去）は **純 scale で ≈0** になる。
  だが実際の TV は 0.055（T=1）——**偽OK**。
- `divergence_rms`（total）は **純 shift で 3.0** になる。だが実際の TV は厳密に 0——
  tanh 上界が飽和して **偽BLOCK**。

⇒ 正しいのは **shift のみを除いた第 3 の量**
`ε_i = ‖(b_i − mean b_i) − (a_i − mean a_i)‖∞`（`decision.sampling_epsilon`）。

### 上界と、その正直な限界

`‖p−q‖_TV ≤ tanh(ε/T)`（確率比が `[e^{−2ε/T}, e^{2ε/T}]` に収まることの帰結・
**一次近似でなく大域的**）。実測でタイト（`max TV/tanh = 1.0000`）。
指示書が出発点に挙げた係数 1/2 型は実測比 2.0 で破れる——A-5 と同じく
「係数は数値実験で確かめてから入れる」が効いた例。

ただし **低温では上界が 1 に飽和して無情報**（T=0.1 で「TV ≤ 0.98」だが実測 0.028）。
fail-safe だが額面通り BLOCK に使えば偽BLOCK を量産するので、判定は *実測* TV で行い、
上界は併記に留め、無情報なら自ら INFO で申告する（SAFETY 校正が達成信頼度を毎回出すのと同型）。

### サンプリング層は本視点の一般化である

TV は最適結合の下で「両ベンダーから引いた 1 サンプルが食い違う確率」そのもの。
T→0 では分布が argmax の点質量に潰れるので、その確率はちょうど argmax フリップ率になる。
実測でも T=0.01 で mean TV=0.0281 に対し argmax フリップ率 0.0275。
**貪欲は T→0 の特例**であり、`flip_rate` の意味はタスク間で一貫している
（だから同じ `flip_budget` と比較できる）。

残: beam search（Q22）は未対応。`compare_task(ranking)` の top-k 集合変化と `rollout` の
系列合成の再利用が主だが、`decode="beam"` が `ValueError` を送出することを固定した負の
テストがあるため、それを意図的に壊す独立ラウンドで扱う。

## 追補2: 予測は「どれだけ境界を踏んだか」で信頼性が決まる（A-9/Q21）

`predicted_flip_bound` は代表集合の margin 分布から `P(margin<2δ)`（判断フリップ率の上界）を
推定する。だがこの予測の信頼性は、代表集合が **決定境界をどれだけ実際に踏んでいるか** で決まる。

### 問題: 大マージンばかりの集合は本番を過小評価する

softmax の argmax がフリップするのは near-tie（margin < 2δ）のサンプルだけ。代表集合が
大マージンに偏っていると near-tie をほとんど含まず、near-tie が多い本番のフリップ率を
過小評価する（偽OK）。実測: 大マージン代表集合の予測 4.0% に対し、境界近傍に入力が集中する
本番の実フリップ率 13.6%（3.4 倍）。

### Wilson では閉じない

`predicted_flip_bound` は Wilson 上側限界で「k/n 比率の不確実性」を織り込むが、これは
*与えられた集合* の `P(margin<2δ)` を忠実に上界するだけ。**その集合が本番を代表しているか**は
Wilson の管轄外である。size（n が小さい）は Wilson が扱うが、representativeness（分布が違う）は
扱えない。

### 超過数 k が信頼性を支配する

`P(margin<2δ)` は決定境界近傍の *裾* 確率。裾確率推定の相対不確実性は total n でなく
**超過数 k**（= margin<2δ のサンプル数）に支配される——二項比率の相対標準偏差は ≈1/√k で
n に依らない（k=4→50%・k=30→18%・k=100→10%）。極値理論（peaks-over-threshold）でも
安定な裾推定には超過数 30〜50 以上が要るとされる。`flip_bound_support` はこの k を報告し、
不足なら「n を増やすのでなく *決定境界近傍* のサンプルを増やせ（境界を重点サンプリング）」と促す。

### fail-safe の判断: 透明化であって追加の門ではない

この診断は判定を変えない。Wilson が既にフリップ率上界の値を保守化しているため、裾サポート
不足に追加の WARN を課すと二重計上になる（SAFETY 校正ラウンドで標本不足を INFO にしたのと
同じ判断）。予測がどれだけ境界を踏んでいるかを透明化し、代表集合の作り方を導くに留める。
出典と実測は docs/SOURCES.md「代表集合の裾サポート」節。
