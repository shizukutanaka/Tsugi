# 新視点8: タスクレベル等価性 — 判断は数値でなく決定で測る

ソクラテス式問答・第8ラウンド。`tsugi.decision` として実装。

## 問答

**Q1. これまでの全 7 視点は何を測ってきたか？**
「数値がどれだけ違うか」—— max_abs / rel / 系統バイアス / run-to-run ノイズ。すべて
*テンソル空間* の差。

**Q2. 開発者が出荷するのはテンソルか？**
否。出荷するのは **タスクの判断** —— 分類の argmax、言語モデルの選択トークン、検出の
しきい値判定。ユーザーが見るのは logit の値でなく「どのクラス/トークンが選ばれたか」。

**Q3. 数値発散とタスクの判断は同じものか？**
否。**decouple している**。
- **スケール不変**: logit を 10 倍すれば abs 誤差も 10 倍になるが argmax は不変
  → 判断フリップ率は同一。max_abs は判断を測れていない。
- **数値等価 ⇏ タスク等価**: 巨大な数値発散でもマージンが大きければフリップ 0、
  微小な発散でも near-tie ならフリップ。両者は必要十分の関係にない。

**Q4. では何が判断のフリップを支配するのか？**
局所 **マージン（top1 − top2）**。発散 δ が判断を覆すには **margin < 2δ** が *必要*
（十分ではない）。ゆえにフリップ率 ≤ P(margin < 2δ) という保守的な上界が成り立つ。

**Q5. これは既存視点とどう関係するか？**
**翻訳層**。数値の床（calibration の √K·u）も HW の床（nondeterminism のノイズ）も、
*タスク影響* に翻訳して初めて意味を持つ。橋は **マージン分布**:
発散 δ → P(margin < 2δ) → 判断フリップ率。タスク相対の許容は固定 atol でなく
マージン分布であり、検証の最終単位は **テンソルでなく決定**。

## 実証（numpy・CPU）

2 万サンプル・1000 クラスの logit にクロスベンダー数値発散 ε を加え、argmax の
フリップ率を測る:

```
eps=1e-3: max_abs=0.008  判断フリップ率= 0.24%  フリップ群マージン中央値=0.001 vs 全体0.212
eps=1e-2: max_abs=0.082  判断フリップ率= 2.60%  フリップ群マージン中央値=0.009 vs 全体0.212
eps=1e-1: max_abs=0.816  判断フリップ率=23.86%  フリップ群マージン中央値=0.069 vs 全体0.212
```
→ フリップは **低マージン（near-tie）の裾に集中**する（フリップ群の中央値 ≪ 全体）。

**スケール不変性（max_abs は判断の悪い代理）**:
```
logit 等倍 : max_abs=0.082  フリップ率=2.60%
logit 10倍 : max_abs=0.816  フリップ率=2.60%   ← abs 誤差 10 倍でもフリップ率は同一
```

**P(margin < 2δ) は実フリップ率の上界**（保守的・fail-safe）:
```
eps=1e-3: 実 0.24%  ≤ 予測 0.76%
eps=1e-2: 実 2.60%  ≤ 予測 8.98%
eps=1e-1: 実23.86%  ≤ 予測60.81%
```

**数値発散 ⇏ タスク発散**: マージンの大きい（確信した）モデルは max_abs≈0.37 の
相当な数値発散でも判断フリップ率 < 0.5% に留まる。

## 含意

- 検証の最終単位は **テンソルでなく決定**。「数値がどれだけ違うか」でなく
  「何 % の予測がベンダー間で変わるか」を問う。
- デプロイ判断には数値 atol でなく **タスク予算**（例 フリップ率 < 0.1%）を使う。
- フリップは near-tie 裾に集中するのが健全。**確信予測まで変化するなら系統的発散を疑う**
  （decision の健全性チェック）。これは calibration の系統バグ検出とタスク空間で呼応する。
- 数値検証（視点 1-7）は依然必要 —— だが「目的」でなく「タスク影響を予測する手段」。
  橋は margin 分布。

## API

```python
from tsugi.decision import (
    margin,                # top1-top2（判断の頑健さ）
    flip_rate,             # 判断フリップ率（スケール不変・ユーザーに見える差）
    predicted_flip_bound,  # P(margin<2δ)= 数値発散→タスク影響の保守的上界
    compare_decisions,     # タスクレベル等価判定（フリップ率 vs タスク予算）
)
```
