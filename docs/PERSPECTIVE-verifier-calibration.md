# 新視点6: 検証器そのものの検証 — 偽OK の非対称コストと検出限界

ソクラテス式問答・第6ラウンド。`tsugi.calibration` として実装。

## 問答

**Q1. これまで 8 層を作った。すべて「カーネル/モデルを検証する」。では検証器自身は誰が検証したのか？**
誰もしていない。検証器は thresholds と数値モデル（tolerance=√K·u·safety, occupancy=HW定数,
envelope=IEEE限界, propagation=条件数）で OK/WARN/BLOCK を出すが、その判定が正しい保証はない。

**Q2. 検証器が間違うとき、誤りは対称か？**
否。二種類あり、コストは**非対称**。
- **偽BLOCK**（移植可を不可と言う）= 開発者が気づける・回復可能。せいぜい不採用。
- **偽OK**（発散を等価と言う）= オラクルの無いもう片方のベンダーに *silent な誤り* を出荷。
  検出不能で致命的。これが検証器の**最大の罪**。

→ コストが非対称ゆえ、検証器は不確実なら **BLOCK 寄りに倒す**べき（fail-safe）。

**Q3. では許容ベースの等価判定（視点1・2）は、どんなバグなら確実に捕まえるのか？**
正当な累積発散より**大きい**バグだけ。許容 atol = safety·√K·u·scale の帯に隠れる
誤差は原理的に見えない。これを**検出限界（detectability floor）**と呼ぶ。
相対 floor = safety·√K·u（scale 非依存）。

**Q4. floor は固定か？**
否。**K とともに √K で拡大する**。fp16:
| K | 検出限界（相対） |
|---|---|
| 256 | 3.1% |
| 2048 | 8.8% |
| 8192 | 17.7% |

つまり大K GEMM ほど検証器は大きな系統誤差に**盲目**になる。

**Q5. これは何を意味するか？**
**視点2（導出許容）自身の代償**。導出許容は大K GEMM の偽BLOCK（固定 1e-2 の過剰検出）を
消したが、同時に偽OK の盲点を √K で広げていた。どの修正にも双対のコストがある。

## 実証（numpy・CPU）

0.5% の系統スケール誤差（一方のベンダーが一様に 1.005 倍する実バグ）を仕込む:

```
出力scale=45.4 導出atol=4.016
相対検出限界 = atol/scale = 8.8%  ← これ未満の系統誤差は max_abs では不可視

順序(等価)        : max_abs判定=EQ  バイアス(RMS比)=+0.000%
0.5%スケール(バグ) : max_abs判定=EQ(見逃し=偽OK)  バイアス=+0.500%
ブロック落ち(バグ)  : max_abs判定=DV(捕捉)        バイアス=-6.713%
```

ground-truth コーパス（等価3 + バグ6）での検証器の採点:
```
max_abs 単独 : UNTRUSTWORTHY  false-OK = 3/6 (50%)  見逃し: scale
合成(相補)   : TRUSTWORTHY    false-OK = 0/6 (0%)
```

## 救済 — scale/K 不変な相補計量

max_abs は**乱雑・局所的**な発散に効く。系統的（相関）バグには **RMS（エネルギー）比**が効く:
- 正当な累積順序差は **zero-mean** → RMS 比 ≈ 0
- 系統バグ（スケール/バイアス）は**相関** → RMS 比 ≠ 0、しかも **K 不変**

| K | max_abs 検出限界 | RMS比@0.5%バグ | max_abs 判定 |
|---|---|---|---|
| 256 | 3.1% | 0.500% | EQ（見逃し）|
| 2048 | 8.8% | 0.500% | EQ（見逃し）|
| 8192 | 17.7% | 0.500% | EQ（見逃し）|

RMS 比は全 K で 0.5% を捉える。閾値は safety·u（√K を掛けない＝K 不変）。
`is_equivalent_combined` は max_abs と系統検査の **両方** を見て、どちらかが発散を示せば
DIVERGENT に倒す（fail-safe）。これでコーパスの偽OK がゼロになる。

## 含意

- 検証器は「assertions」から「**測定された instruments**」になる。floor を明示し、
  自分が見逃す誤差の下限を申告する。
- 単一計量（max_abs）に頼る等価判定は、非対称コスト下では危険。**相補的な計量の合成**が要る。
- これは 9 個目の siloed な視点ではなく、既存の等価層（視点1・2）を**較正・補完**する
  メタ層。検証スタックの信頼性そのものを定量化する。

## API

```python
from tsugi.calibration import (
    detectability_floor,      # max_abs が見逃す誤差の下限（K で拡大）
    systematic_divergence,    # RMS 比 -1（scale/K 不変な系統誤差指標）
    check_systematic,         # 系統バイアス検査（max_abs の盲点を埋める）
    is_equivalent_combined,   # fail-safe 合成判定（max_abs + 系統）
    make_corpus, evaluate,    # ground-truth で検証器の偽OK率を測るメタ層
)
```
